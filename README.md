# VeraCraft — magicpin AI Challenge

## Approach

This submission implements a context-grounded Vera assistant. With `GEMINI_API_KEY`
configured, Gemini rewrites grounded outbound drafts and handles natural-language
merchant/customer replies. Without a key, the service uses its deterministic local
composer and reply state machine.

Both paths use the four pushed context layers:

- **Category:** vertical voice, peer benchmarks, digest items, and catalog patterns.
- **Merchant:** identity, locality, performance, verified offers, subscription, and signals.
- **Trigger:** the event that explains why Vera is contacting the merchant now.
- **Customer:** relationship, language preference, consent-related outreach context, and
  appointment/recall details when the message is sent on the merchant's behalf.

Code continues to enforce routing, purpose-specific customer consent, WhatsApp preference,
opt-out handling, supported triggers, and structured response validation. Customer
messages are withheld when consent or required context is missing. Model prompts treat
context as data rather than instructions, redact direct identifiers and medication fields,
and reject unsupported numeric claims. The model must not invent facts or claim it actually
sent a campaign, booked an appointment, or completed another external action.

Gemini is called over HTTPS using Python's standard library; no provider SDK is required.
The model response timeout defaults to 12 seconds (maximum 20 seconds), and a tick reserves
time for the challenge's 30-second endpoint limit. A failed composition is logged and
withheld; a failed reply returns HTTP 503 rather than fabricated copy. Temperature is set
low, but model output is not guaranteed to be perfectly deterministic. The canonical
`submission.jsonl` remains generated by the deterministic composer.

Customer messages may contain sensitive health or pharmacy information. The implementation
removes common identifiers and medication fields from context sent to Gemini, but free-text
replies can still contain sensitive information. Review Google AI Studio's current data
handling terms and use only data you are authorized to process.

## API and state

`server.py` exposes the required `GET /v1/healthz`, `GET /v1/metadata`,
`POST /v1/context`, `POST /v1/tick`, and `POST /v1/reply` endpoints, plus the optional
`POST /v1/teardown` endpoint. `ContextStore` is thread-safe and supports atomic
higher-version replacement and same-version idempotent replay.

Hard reply safeguards and offline behavior:

1. Sends one human-owner nudge for the first canned auto-reply.
2. Waits 24 hours after a repeated auto-reply.
3. Ends after the third repeated auto-reply.
4. Ends immediately on an explicit opt-out/hostile message.
5. Switches directly to action mode when the merchant commits.
6. Treats a bare affirmative as commitment only when it follows a recorded binary action.

When configured, Gemini handles other merchant and customer replies using the current
message, recent conversation turns, and minimal relevant context. It can choose `send`,
`wait`, or `end`; customer replies are not interpreted as proof that a booking or order
was completed.

## Run locally

```powershell
python server.py
python test_bot_local.py
python generate_submission.py
```

The server listens on port `8081` by default. `submission.jsonl` contains the generated
30-line canonical submission. To enable Gemini in PowerShell, set the key in the current
terminal before launching the service:

```powershell
$env:GEMINI_API_KEY = "your-key"
$env:GEMINI_MODEL = "gemini-3.8-flash"
python server.py
```

Do not commit the key. A missing key leaves the deterministic implementation active.

## Deploy on Render

The repository includes `render.yaml`, `requirements.txt`, and `.python-version`.

1. Push the project to a GitHub repository.
2. In Render, choose **New + → Blueprint** and connect that repository.
3. Review the `veracraft-bot-gemini` web service. The Blueprint defaults to Render's free plan.
   Free instances can spin down when idle; upgrade to a paid plan before evaluation if
   the challenge requires uninterrupted availability.
4. Enter `VERA_TEAM_NAME`, `VERA_CANDIDATE_NAME`, `VERA_CONTACT_EMAIL`, and your Gemini
   API key when prompted. Set `GEMINI_MODEL` to a model enabled for your AI Studio key;
   `render.yaml` defaults to `gemini-3.8-flash`.
   Optionally set `VERA_SUBMITTED_AT` to the submission timestamp in ISO-8601 UTC format;
   otherwise metadata reports the service process start time.
5. Deploy, then verify `https://<your-service>.onrender.com/v1/healthz` and
   `/v1/metadata`.
6. Submit the base HTTPS URL to the challenge portal and keep the service running.

The outbound action includes a one-parameter template (`{{1}}`) containing the composed
message body, plus its `template_params` value.

Gunicorn is configured with one worker because context and conversation state are held
in memory; multiple workers would maintain separate, inconsistent copies of that state.
The service must remain available throughout evaluation. Render's free instances can
spin down and restart, which temporarily affects availability and clears in-memory state.

## Tradeoff

The deterministic baseline favors verifiability and safe restraint when context is
incomplete. Gemini improves phrasing and open-ended dialogue but cannot make unsupported
triggers eligible for outreach or override the application's hard safety checks.
